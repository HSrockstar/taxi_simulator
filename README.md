# 智能网约车平台派单与运力调度模拟器

《数据结构与算法设计》课程设计（题目 3）：在 1000×1000 的虚拟城市中模拟网约车平台的实时派单与动态运力调度。系统手工实现了网格空间索引、订单队列、最小堆撮合等核心数据结构，通过 Web 可视化展示供需热力图、派单实时日志与全局指标。

## 功能特性

- **网格化流式撮合**：100 辆带评分的出租车随机分布在 100×100 的网格矩阵中，订单队列按先来先服务处理，每个模拟秒批量派单一次（引擎 tick 为 100ms，每秒 10 拍）。
- **路况感知撮合评分**：网格内维护 `1.0 / 1.5 / 2.5` 三档道路通行系数；对当前网格及相邻 3 格内的空闲司机，沿直线路径采样网格并估算接驾 ETA，计算 `Score = ETA(秒) - 0.5 × 司机评分`，候选压入手工实现的最小堆，堆顶即最优司机。
- **供需失衡动态调度**：统计每个网格的 `订单数 - 空车数`，差值超阈值的格子标记为红色热点区（模拟器内置 3 个热点区域，每 30 秒轮换），自动从半径内富余网格中、按与撮合同款的最小堆评分挑选最优供体司机前往。
- **空闲司机游走**：空闲司机每个 tick 以 5% 概率移动一格（平均每秒 0.5 步，8 邻域随机方向），避免撮合半径之外的运力永久静止；处于调度半径之外的空闲车迈步时以 70% 偏置向当前活跃热点缓慢漂移，半径内的运力仍由显式调度机制主导，游走中的司机随时可被撮合或调度打断。
- **状态机流转**：司机有 `空闲 / 接客途中 / 行程中 / 调度中` 四态，订单有 `等待 / 已匹配 / 已完成 / 已取消`（超时未匹配则取消）四态。撮合成功后司机按用于撮合的路况 ETA 前往上车点（至少保留一个模拟节拍），接到乘客进入 8–20 秒行程，到达目的地订单才算完成，期间在途订单按司机槽位关联记录，并产生 `[行程开始]`、`[行程完成]` 日志。
- **运行时参数热调节**：司机数、每秒订单率、撮合半径、调度半径、失衡阈值、订单超时均可通过看板"引擎参数调节"面板或 `POST /api/params` 实时修改，保存后立即生效于下一个模拟节拍；修改司机数会即时增减运力。
- **Web 可视化看板**：
  - 网格供需热力图（订单多变红、空车多变绿；路况以斜线叠层区分缓行/拥堵），可直观看到司机向热点区转移；
  - 调度流向动画：司机被调往热点时绘制起点到目标格的渐隐路径，司机点沿路径移动；
  - 接客/行程在途渲染：前往接客的司机显示橙色虚线路径与光点，行程中的司机显示紫色虚线路径与光点，位置逐 tick（100ms）推进；
  - 派单实时日志（匹配双方、距离、预计接驾时间、平均路况系数、评分、撮合耗时、行程开始/完成/取消）；
  - 全局指标卡片与趋势图（队列长度、派单成功率、平均/总撮合耗时、完成行程等）。
  - 后端通过 SSE（Server-Sent Events）把快照实时推送到前端，数据一变即推送，无需轮询。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | C++17、WinSock2 手写 HTTP 服务器（每连接一线程 + SSE 实时推送）、std::thread 多线程 |
| 前端 | Vue 3 + TypeScript + Vite（构建产物输出到 `web/`，由 C++ 服务静态托管） |
| 构建 | Make + MSYS2 UCRT64 g++、npm |

## 环境要求

- Windows（后端使用了 WinSock2 与 Shell API）
- [MSYS2](https://www.msys2.org/) UCRT64 工具链，Makefile 中默认编译器为 `C:/msys64/ucrt64/bin/g++.exe`（路径不同时请修改 Makefile）
- Node.js + npm（仅构建前端时需要）

## 构建与运行

```bash
# 1. 构建前端并编译后端（产物：taxi_simulator.exe）
make all

# 2. 启动模拟器（默认自动打开浏览器）
./taxi_simulator.exe
```

可执行文件静态链接了 C++ 运行库（`-static`），是免依赖的单文件 exe，双击或拷贝到其他 Windows 机器均可直接运行。

访问 <http://127.0.0.1:8080> 即可看到看板。按 `Ctrl+C` 安全退出。

### 命令行参数

```text
taxi_simulator.exe [--port 8080] [--seed 20260808] [--duration 秒数] [--no-browser]
```

| 参数 | 说明 |
| --- | --- |
| `--port` | HTTP 服务端口，默认 `8080` |
| `--seed` | 随机种子（相同种子可复现模拟过程） |
| `--duration` | 运行指定秒数后自动退出，默认一直运行 |
| `--no-browser` | 启动时不自动打开浏览器 |

### 前端独立开发

```bash
npm --prefix frontend install
npm --prefix frontend run dev     # http://localhost:5173，/api 已代理到 127.0.0.1:8080
```

## 核心设计

### 手工实现的数据结构（`src/manual_structures.*`）

- **GridIndex**：100×100 网格矩阵，坐标到网格 O(1) 定位，每格维护空闲司机双向链表，支持 O(1) 增删与跨格移动。
- **OrderQueue**：链式队列存储未处理订单，互斥锁保护，先来先服务。
- **MinHeap**：动态数组的二叉最小堆，存放撮合候选（司机、分数、距离），堆顶为最优匹配；同分时依次按距离、评分、司机 ID 决胜，保证结果确定性。
- **LogRingBuffer**：容量 200 的环形缓冲区，保存最近日志并按序号增量输出给前端。

### 模拟流程（`src/simulator.*`）

单一调度线程每 100ms 执行一次 tick（`kTicksPerSecond = 10`，即每模拟秒 10 拍），所有逻辑在一个状态锁内按固定顺序运行：每 5 个模拟秒刷新一次由热点和两处周期事故点构成的路况系数 → 处理司机状态回退（接客到达转入行程、行程完成回归空闲、调度到达回归空闲）与空闲司机游走（每 tick 5% 概率移动一格、平均每秒 0.5 步，调度半径外附带向活跃热点的定向漂移，跨格时经 `GridIndex::moveDriver` 迁移链表）→ 每个模拟秒批量生成 5–10 个订单（80% 集中在热点区，热点每 30 秒在三处坐标间轮换）→ 批量派单（出队订单 → 扫描当前格及相邻网格空闲司机 → 沿直线路径采样网格、计算 ETA → 代价分数压入最小堆 → 取堆顶匹配，司机按该 ETA 前往接客）→ 统计各格供需差，对**超过**失衡阈值的格子从半径内富余网格中按同款 ETA 评分最小堆挑选最优供体司机调度前往。评分公式为 `Score = ETA(秒) - 0.5 × 评分`。订单等待超过 10 秒未被匹配则自动取消；撮合成功的订单与司机槽位关联，行程结束时流转为已完成并累计 `completed` 指标。以 tick 计的时长（接客 ETA、行程 8–20 秒、调度 2 秒、超时）均按 `kTicksPerSecond` 与秒互转。

由于订单生成与撮合由同一线程、同一随机序列驱动，**相同种子下模拟过程完全确定、可逐 tick 复现**（测试 `testDeterminism` 验证）。

### 可调参数（`src/model.h`）

地图与网格规模为编译期常量；以下模拟参数支持运行时热更新（看板"引擎参数调节"面板或 `POST /api/params`），表中为默认值与合法范围：

```cpp
kMapSize = 1000              // 城市边长（编译期常量）
kGridSide = 100              // 网格边数，每格 10×10（编译期常量）
kMaxDriverCount = 500        // 司机数组容量上限（编译期常量）
```

| 参数 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| `driverCount` 司机数 | 100 | 10–500 | 增加即时生成新空闲司机，缩减即时移除多余运力 |
| `orderRateMin/Max` 每秒订单率 | 5–10 | 0–50 | 每个模拟秒（10 tick）生成的订单数量区间 |
| `matchRadius` 撮合半径 | 3 | 1–20 | 撮合扫描的网格半径 |
| `rebalanceRadius` 调度半径 | 10 | 1–30 | 热点调度搜索供体的网格半径 |
| `imbalanceThreshold` 失衡阈值 | 2 | 1–20 | 当 `订单数-空车数` 严格超过该值时触发调度 |
| `orderTimeout` 订单超时 | 10 | 1–60 | 订单等待多少秒后自动取消 |

### 演示推荐参数

在题目给定的供需约束下（100 辆出租车、每秒 5–10 个订单），经批量仿真扫参分析（详见
[参数调优分析.md](参数调优分析.md)），失衡调度机制的展示效果最优、同时保持真实可信的参数组合为
（数值为当前引擎口径下 3 个随机种子的稳态区间）：

| 场景 | `matchRadius` | `rebalanceRadius` | `imbalanceThreshold` | `orderTimeout` | 预期表现 |
| --- | --- | --- | --- | --- | --- |
| **主推演示** | 6 | 30 | 1 | 20 | 成功率 ~48–49%，调度动画 ~135 次/分，警报格 ~12 个，"绿转红"全程可见 |
| 机制戏份最足 | 3 | 30 | 1 | 15 | 成功率 ~42–43%，热点订单几乎全靠调度送车，路况感知日志占比最高 |
| 调度机制对照 | 5 | 1 | 5 | 20 | 成功率 ~15%、76–79% 司机闲置——用于对比突出调度机制贡献 |
| 默认参数 | 3 | 10 | 2 | 10 | 成功率 ~16%，作为"机制未激活"的叙事起点 |
